## 概述

### 什么是 Voice Mode？

Voice Mode 是 Claude Code v2.1.69 引入的语音编程功能，通过语音输入代替键盘打字。

```
传统模式：
你 → 打字输入 → Claude 响应 → 打字输入 → ...

Voice Mode：
你 → 说话 → Claude 响应 → 说话 → ...
```

### 核心特点

| 特点 | 说明 |
|------|------|
| Push-to-Talk | 按住说话，松开发送 |
| 非持续监听 | 不是"始终监听"，更加精确可控 |
| 技术术语优化 | 针对代码和仓库名称优化 |
| 多语言支持 | 20 种语言，包括中文 |

## 核心机制

### Push-to-Talk 工作流

```
1. 按住空格键
      ↓
2. 开始说话（屏幕显示波形动画）
      ↓
3. 松开空格键
      ↓
4. 语音被转换为文字
      ↓
5. Claude 处理并响应
      ↓
6. 等待下一轮输入
```

### 与传统输入的对比

| 方面 | 键盘输入 | Voice Mode |
|------|----------|------------|
| 速度 | 中等 | 快（说话速度） |
| 准确性 | 100% | ~95%（依赖识别） |
| 适用场景 | 精确代码、复杂描述 | 快速迭代、头脑风暴 |
| 环境要求 | 安静 | 需要麦克风环境 |

## Windows 配置

### 基本要求

| 要求 | 说明 |
|------|------|
| 麦克风 | 支持 Windows 音频输入 |
| 驱动 | 最新的音频驱动 |
| 权限 | Claude Code 麦克风权限 |

### 权限设置

**Windows 11**:
1. 打开「设置」→「隐私与安全性」
2. 选择「麦克风」
3. 确保 Claude Code 有麦克风权限

```powershell
# 检查麦克风是否正常工作
Get-AudioDevice -Recording | Format-List
```

### 快捷键自定义

可以在 `keybindings.json` 中自定义语音快捷键：

```json
{
  "keys": ["voice:pushToTalk"],
  "command": "voice.push-to-talk",
  "when": "voiceModeActive"
}
```

### 组合键支持

Voice Mode 支持组合键绑定：

```json
// Mac: Cmd+K
{ "keys": ["meta", "k"], "command": "voice.push-to-talk" }

// Windows: Alt+K
{ "keys": ["alt", "k"], "command": "voice.push-to-talk" }
```

## 实战场景

### 场景 1: 快速头脑风暴

```bash
/voice

# 按住空格，说：
"我想要一个电商网站的购物车功能，包含添加商品、
修改数量、删除商品和计算总价"

# 松开空格，Claude 给出设计方案
```

**优势**: 说话比打字快 3-5 倍，适合快速迭代想法

---

### 场景 2: 边做边说（Hands-free）

```bash
/voice

# 双手在做其他事情时
"把登录按钮的颜色改成蓝色，加上 hover 效果"

"再添加一个忘记密码的链接"
```

**适用**:
- 阅读代码同时记录想法
- 测试时快速描述修改
- 双手忙碌时继续工作

---

### 场景 3: 复杂需求描述

```bash
/voice

# 按住空格，说：
"创建一个 API 中间件，需要处理 JWT 验证、
请求日志记录、错误捕获和返回格式化，
还要支持自定义错误码和重试机制"
```

**优势**: 语音可以更自然地描述复杂逻辑

---

### 场景 4: 代码审查口述

```bash
/voice

# 审查代码时
"这个函数的命名不太清晰，建议改成 getUserById
而且这里没有做空值检查，可能会有 NPE"
```

**优势**: 边看边说，比打字更流畅

## 最佳实践

### 1. 清晰的发音

```
❌ 模糊发音
   "那个...呃...就是...你知道吧"

✅ 清晰发音
   "创建一个用户验证函数"
```

### 2. 适当的句子长度

```
❌ 句子太长
   "帮我创建一个包含用户名校验、邮箱格式校验、密码强度校验、确认密码匹配的完整注册表单，包含前端界面和后端 API，还要有错误提示和加载状态"

✅ 分段表达
   "帮我创建一个用户注册表单"
   "包含用户名、邮箱、密码和确认密码字段"
   "添加表单校验逻辑"
```

### 3. 技术术语使用

Voice Mode 对技术术语有优化：

```bash
# 建议使用标准术语
"创建 async 函数处理 API 请求"
"添加 useEffect hook"
"修复 useState 的类型错误"

# 避免使用模糊指代
# ❌ "那个东西" "上面说的那个"
# ✅ 明确说出具体的函数名、变量名
```

### 4. 网络和麦克风检查

```powershell
# Windows 检查麦克风
Get-AudioDevice -Recording

# 检查网络（语音需要上传音频）
Test-NetConnection -ComputerName api.anthropic.com -Port 443
```

### 5. 中英文混用

技术术语通常用英文，中文描述需求：

```bash
# ✅ 推荐
"创建一个 useUserData hook，获取用户信息并处理 loading 和 error 状态"

# ⚠️ 备选（识别可能不稳定）
"创建一个 hook 叫 useUserData"
```

## 常见问题

### Q1: Voice Mode 没有反应怎么办？

**检查项**:

1. **麦克风权限**
   ```powershell
   # Windows 检查麦克风权限
   Get-AppxPackage -Name "*claude*"
   ```

2. **麦克风是否正常工作**
   ```bash
   # 测试麦克风输入
   # 在系统设置中测试录音
   ```

3. **网络连接**
   ```powershell
   Test-NetConnection api.anthropic.com -Port 443
   ```

4. **重新激活**
   ```bash
   # 输入 exit 退出，再重新激活
   /voice
   ```

---

### Q2: 语音识别不准确怎么办？

**提高准确率的方法**:

1. **靠近麦克风说话**
2. **减少背景噪音**
3. **使用耳机**（防止回声）
4. **说话语速适中**
5. **技术术语用英文**

---

### Q3: 如何退出 Voice Mode？

**方法**:

```bash
# 输入 exit
exit

# 或按 Ctrl+C
Ctrl+C
```

---

### Q4: 能否在 Voice Mode 中使用键盘输入？

**可以**。Voice Mode 支持混合使用：

```bash
# 语音输入主要指令
"创建一个 React 组件"

# 用键盘补充细节
用户输入: "组件名叫 UserProfile，放在 components 目录下"
```

---

### Q5: Windows WSL 环境下能用吗？

**能**，但有一些改进：

- 音频路由更稳定
- 延迟更低
- 建议使用 WSL 2

---

### Q6: 支持语音反馈吗（文字转语音）？

**不支持**。Voice Mode 是单向的：
- 输入: 语音 → 文字
- 输出: 文字 → 语音（暂无）

---

### Q7: 隐私问题，音频会被保存吗？

根据官方说明：
- 音频在处理后立即删除
- 不会用于模型训练
- 符合 Anthropic 隐私政策
