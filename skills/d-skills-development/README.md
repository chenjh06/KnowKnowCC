## 📊 类别概述

**Skills 开发** 是 Level 2 的第四个类别，专注于教你如何创建和管理 Claude Skills。

### 为什么学习 Skills 开发?

```
❌ 不学习 Skills 开发:
├─ 每次重复说明工作流程
├─ 团队知识难以传承
├─ 个人效率无法进一步提升
└─ 错过 Claude Code 最强大的功能

✅ 掌握 Skills 开发:
├─ 创建自定义斜杠命令
├─ 编码团队最佳实践
├─ 效率再提升 2-3 倍
└─ 成为团队效率专家
```

### 核心价值

1. **编码知识**: 将个人和团队的最佳实践转化为可复用的技能
2. **提升效率**: 一条命令完成复杂的多步骤任务
3. **团队协作**: 统一工作流程，减少沟通成本
4. **持续改进**: 技能可以不断优化和迭代

### 学习目标

完成本类别后，你将能够:

- ✅ **独立设计**实用 Skills（从 5 行到 60+ 行）
- ✅ **理解核心概念**（参考内容型 vs 任务型、调用控制）
- ✅ **掌握高级特性**（子代理、Hooks、工具限制、参数传递）
- ✅ **优化触发率**到 80%+
- ✅ **部署和分发**技能（个人、项目、插件三种方式）
- ✅ **测试和验证**技能质量
- ✅ **建立技能库**（个人或团队）

## 📖 文档详解

### 01 - Skill Fundamentals (基础概念)

**目标**: 深入理解 Skills 的核心概念

**内容**:
- Skills 的两种类型（参考内容型 vs 任务型）
- SKILL.md 完整结构（frontmatter + 内容）
- 核心字段详解（name, description, argument-hint, disable-model-invocation等）
- 调用控制矩阵（双向、仅手动、仅自动）
- Windows 路径处理技巧
- 分析 3 个官方 Skills 示例

**实战案例**: 3 个分析案例

**预计时间**: 45 分钟

**学习后能够**:
- ✅ 理解两种类型的区别和使用场景
- ✅ 熟练配置 frontmatter 字段
- ✅ 控制技能的调用方式
- ✅ 分析和理解现有技能

### 02 - Practical Skills (实战案例)

**目标**: 通过 5 个渐进式案例掌握开发流程

**内容**: 5 个实战案例（从简单到复杂）

1. **简单问候技能**（5 行代码）
   - 学习目标: 理解最小 SKILL.md 结构
   - 难度: ⭐
   - 时间: 10 分钟

2. **代码解释器**（15 行代码）
   - 学习目标: 编写有效 description、使用 argument-hint
   - 难度: ⭐⭐
   - 时间: 20 分钟

3. **测试生成器**（30 行代码）
   - 学习目标: 处理多个参数、限制工具访问
   - 难度: ⭐⭐⭐
   - 时间: 30 分钟

4. **代码审查员**（40 行代码）
   - 学习目标: 使用 `!command` 动态注入、限制 Bash 工具
   - 难度: ⭐⭐⭐
   - 时间: 30 分钟

5. **部署管道**（60 行代码）
   - 学习目标: context: fork、agent 配置、Hooks 生命周期
   - 难度: ⭐⭐⭐⭐
   - 时间: 40 分钟

**预计时间**: 90 分钟（全部完成）

**学习后能够**:
- ✅ 独立设计实用技能
- ✅ 处理参数和工具限制
- ✅ 使用高级特性
- ✅ 创建 60+ 行复杂技能

## 🎯 学习建议

### 学习策略

**策略 1: 边学边做**

```
学习概念 → 动手实践 → 遇到问题 → 查阅文档 → 解决问题 → 巩固知识
```

**策略 2: 渐进式学习**

```
从 5 行代码开始 → 逐步增加复杂度 → 最终掌握 60+ 行技能
```

**策略 3: 实际应用**

```
识别工作中的重复任务 → 设计技能 → 实现并优化 → 分享给团队
```

### 常见误区

**误区 1: 一次性学完所有文档**

❌ **错误**: 试图一次性阅读所有文档
✅ **正确**: 分批学习，每次深入一个主题，立即实践

**误区 2: 只看不做**

❌ **错误**: 只阅读文档不动手
✅ **正确**: 每个案例都亲自实践，修改和优化

**误区 3: 追求复杂技能**

❌ **错误**: 忽略简单技能，直接追求复杂功能
✅ **正确**: 从简单技能开始，逐步增加复杂度

**误区 4: 忽视测试**

❌ **错误**: 创建技能后不测试
✅ **正确**: 建立测试流程，持续优化触发率
