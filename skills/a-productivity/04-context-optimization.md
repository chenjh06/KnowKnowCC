## 上下文优化概述

### 什么是上下文优化？

**定义**：通过合理管理 Claude Code 的上下文窗口，在保持效果的同时最小化 Token 使用。

**上下文窗口**：
- Claude Code 有 200K token 的上下文窗口
- 包含：系统提示、项目文件、聊天历史、工具输出等
- 超过限制需要滚动窗口（可能丢失早期信息）

**优化目标**：
```
✅ 减少 Token 使用 → 降低成本
✅ 提升响应速度 → 更快交互
✅ 保持信息完整 → 不影响效果
✅ 延长会话寿命 → 减少刷新
```

### 为什么重要？

#### 1. 成本控制

```
优化前：
每次对话都加载大量文件
Token 消耗：20,000-30,000/次
月成本：$30-50

优化后：
只加载必要的文件
Token 消耗：5,000-10,000/次
月成本：$10-20

节省：50-70%
```

#### 2. 速度提升

```
上下文越大 → 处理越慢
优化后：
- 响应速度提升 30-50%
- 工具调用更快
- 滚动窗口减少
```

#### 3. 会话持续性

```
优化前：20-30轮对话后需要刷新
优化后：50-100轮对话仍然流畅
```

## Token 基础知识

### 什么是 Token？

**定义**：Token 是文本的最小单位，约等于 0.75 个英文单词。

**粗略估算**：
```
1 Token ≈ 4 个英文字符
1 Token ≈ 2 个中文字符
1 Token ≈ 0.75 个单词
```

### 上下文组成

```
200K Token 上下文窗口
├─ 系统提示：~10K Token (固定)
├─ CLAUDE.md：~5K Token
├─ 项目文件：~50-100K Token
├─ 聊天历史：~50-100K Token
├─ 工具输出：~20-30K Token
└─ 余量：~20K Token
```

### Token 使用监控

查看 Token 使用：

```markdown
# 在对话中输入：
/context

# 输出示例：
=== 上下文使用分析 ===

系统提示：8,234 tokens
项目文件：
  .claude/CLAUDE.md：2,156 tokens
  src/main.ts：15,234 tokens
  src/utils/helpers.ts：8,567 tokens

聊天历史：124,567 tokens
工具输出：15,234 tokens

总计：174,990 tokens / 200,000
余量：25,010 tokens (12.5%)

=== 分析结束 ===
```

## 优化策略

### 策略 1: 精确引用（最重要）

#### ❌ 错误做法

```
❌ 引用整个目录
@src/components/

加载：所有组件文件，可能 50K+ tokens
```

#### ✅ 正确做法

```
✅ 只引用需要的文件
@src/components/UserList.tsx
@src/components/UserCard.tsx

加载：只加载 2 个文件，约 5K tokens
节省：90%
```

#### 实战技巧

**技巧 1：明确指定**

```
❌ 模糊：
"帮我优化组件"

✅ 明确：
"优化 @src/components/UserList.tsx 的渲染性能"
```

**技巧 2：先问后引用**

```
👤 你：src/components/ 目录有哪些文件？

🤖 Claude：[列出文件]

👤 你：读取 UserList.tsx 和 Button.tsx

✅ 选择性加载，避免全目录
```

### 策略 2: 使用 CLAUDE.md

#### 价值分析

```
不使用 CLAUDE.md：
    每次对话都要说明项目规范
    Token：每次 +2,000-5,000

使用 CLAUDE.md：
    一次写入，自动加载
    Token：首次 +5,000，后续 0
    节省：长期节省
```

#### CLAUDE.md 优化

**原则 1：只写必要的**

```markdown
❌ 太详细：
## 项目历史
本项目始于 2020 年，经历了...

✅ 简洁有效：
## 项目概述
电商管理系统 v2.0
React 18 + TypeScript + TailwindCSS
```

**原则 2：结构化**

```markdown
✅ 好的 CLAUDE.md：
# 项目说明

## 技术栈
- 前端：React 18 + TypeScript
- 样式：TailwindCSS

## 代码规范
- 组件：PascalCase
- 工具：camelCase

## 项目结构
src/
├── components/
└── utils/

## 重要约定
- 不要修改 core/
- 所有 API 在 src/api/
```

### 策略 3: 聊天历史管理

#### 问题分析

```
聊天历史消耗：
第 1 轮：1,000 tokens
第 10 轮：10,000 tokens
第 30 轮：30,000+ tokens

滚动窗口：
旧历史被滚动出去，无法引用
```

#### 优化技巧

**技巧 1：定期总结**

```
👤 你：总结我们到目前为止完成的工作

🤖 Claude：[总结对话历史]

👤 你：[确认总结]

✓ 总结后的历史占用更少
```

**技巧 2：使用 /export**

```
定期导出重要对话：
/export

保存到文档后，可以清除历史
需要时重新导入关键信息
```

**技巧 3：新建会话**

```
当前会话历史过多（> 30 轮）：
1. 导出会话 /export
2. 新建项目会话 claude --session new-task
3. 从头开始，上下文干净
```

### 策略 4: 工具输出优化

#### 问题

```
工具输出可能很大：
!npm list          # 输出：5,000 tokens
!ls -laR src/      # 输出：3,000 tokens
!cat large-file.log # 输出：10,000+ tokens
```

#### 优化方案

**方案 1：限制输出**

```bash
!npm list --depth=0    # 只列出顶层包
!ls -la src/          # 不递归
!head -100 file.log   # 只读前 100 行
```

**方案 2：重定向输出**

```bash
!npm test > test-output.txt  # 输出到文件
# 然后选择性查看
!tail -50 test-output.txt
```

**方案 3：使用 grep 过滤**

```bash
!npm list | grep "react"
!cat error.log | grep "ERROR"
```

### 技巧 2: 使用 .claudeignore

#### 什么是 .claudeignore？

类似 .gitignore，告诉 Claude Code 哪些文件/目录**不要**加载到上下文。

#### 创建 .claudeignore

**位置**：项目根目录

```
项目根目录/
├── .claude/
│   ├── CLAUDE.md
│   └── .claudeignore  ← 创建这个文件
```

#### 示例配置

```gitignore
# 依赖和构建产物
node_modules/
dist/
build/
.cache/
.next/
out/

# 日志文件
*.log

*.log.*

# 测试覆盖率
coverage/
.nyc_output/

# IDE
.vscode/
.idea/
*.swp
*.swo

# 临时文件
*.tmp
*.temp
*.bak

# 大型数据文件
*.sqlite
*.db

# 压缩文件
*.zip

*.rar

# 图片和媒体（除非需要）
*.png
*.jpg

# 文档（如果不需要）

# 开发文件

```

#### 实战效果

```
优化前：

.claudeignore 包含 node_modules/
不加载，节省 100K tokens
```

### 技巧 4: 上下文重置

#### 何时需要重置？

```
⚠️ 信号：
- 对话速度明显变慢
- /context 显示 > 80% 使用
- Claude 忘记之前的对话内容
- 需要重新加载上下文

✓ 是时候重置了
```

#### 重置方法

**方法 1：总结 + 新会话**

```
步骤 1：总结
👤 你：总结当前项目的状态和下一步工作

步骤 2：导出
👤 你：/export
保存当前对话

步骤 3：新建会话
👤：[Ctrl+D] 退出
$ claude --session continue-work

步骤 4：恢复上下文
👤 你：这是项目继续工作，[粘贴总结]

**方法 2：使用 /reset（如果可用）**

```

## 常见问题

### Q1: 优化会影响效果吗？

**A**: 不会，反而可能提升效果：

```
✅ 精简的上下文 → Claude 更专注
✅ 减少噪音 → 理解更准确
✅ 明确的目标 → 结果更符合预期
```

---

### Q2: 应该多久清理一次历史？

**A**: 取决于使用频率：

```
轻度使用（每天 1-2 小时）：
每 2-3 周，或 30-40 轮对话

中度使用（每天 4-6 小时）：
每周，或 20-25 轮对话

重度使用（每天 8+ 小时）：
每 3-5 天，或 15-20 轮对话
```

---

### Q3: .claudeignore 会影响功能吗？

**A**: 不会，只会优化：

```
✅ 不加载 node_modules/ → 不会影响代码分析
✅ 不加载 dist/ → 不会影响构建功能
✅ 不加载 logs/ → 不会影响日志查看

例外：如果你需要分析某个文件，显式引用即可：
@node_modules/package.json
```

---

### Q4: 如何处理大型文件？

**A**: 分段处理：

```
❌ 一次性读取：
@large-file.log  # 可能有 50K tokens

✅ 分段读取：
!head -100 large-file.log  # 只读前 100 行
!tail -100 large-file.log  # 只读最后 100 行
!grep "ERROR" large-file.log  # 只提取错误行
```

---

### Q5: 会话历史有自动清理机制吗？

**A**: 是的，通过 `cleanupPeriodDays` 设置：

```
settings.json:
{
  "cleanupPeriodDays": 180  ← 你设置的值
}

含义：
- 180 天后的会话会被自动清理
- 0 = 永不清理
- 30 = 默认值
```
